## 一、Redis内存管理

### 1.1 内存分配

Redis使用jemalloc作为默认内存分配器，支持多种内存分配器：

| 分配器 | 特点 |
|--------|------|
| jemalloc | 默认，内存碎片少 |
| tcmalloc | Google出品，性能好 |
| libc | 系统默认 |

### 1.2 内存查看

```bash
# 查看内存使用
INFO memory

# 查看Key大小
MEMORY USAGE key

# 内存统计
redis-cli --bigkeys
```

## 三、过期策略

### 3.1 惰性删除

访问Key时检查是否过期：

```python
def get(key):
    if is_expired(key):
        delete(key)
        return None
    return key.value
```

### 3.2 定期删除

定期随机检查并删除过期Key：

```python
def active_expire():
    for _ in range(EXPIRE_SAMPLE_SIZE):
        key = random_key()
        if is_expired(key):
            delete(key)
```

### 3.3 设置过期时间

```bash
# 设置过期时间（秒）
EXPIRE key 3600

# 设置过期时间（毫秒）
PEXPIRE key 3600000

# 设置过期时间点
EXPIREAT key 1700000000

# 查看剩余时间
TTL key
PTTL key
```

## 四、内存淘汰策略

### 4.1 淘汰策略列表

| 策略 | 说明 |
|------|------|
| noeviction | 不淘汰，内存满时返回错误 |
| allkeys-lru | 所有Key中淘汰最近最少使用 |
| allkeys-lfu | 所有Key中淘汰最不经常使用 |
| allkeys-random | 所有Key中随机淘汰 |
| volatile-lru | 设置过期时间的Key中淘汰LRU |
| volatile-lfu | 设置过期时间的Key中淘汰LFU |
| volatile-random | 设置过期时间的Key中随机淘汰 |
| volatile-ttl | 淘汰即将过期的Key |

### 4.2 配置淘汰策略

```conf
# 最大内存
maxmemory 1gb

# 淘汰策略
maxmemory-policy allkeys-lru

# LRU采样数
maxmemory-samples 10
```

### 4.3 策略选择建议

| 场景 | 推荐策略 |
|------|---------|
| 缓存场景 | allkeys-lru |
| 有热点数据 | allkeys-lfu |
| 有过期要求 | volatile-lru |
| 不允许丢失 | noeviction |

## 五、内存碎片

### 5.1 查看碎片率

```bash
INFO memory
# mem_fragmentation_ratio: 1.5
```

### 5.2 碎片率说明

| 碎片率 | 说明 |
|--------|------|
| < 1 | 使用了swap，性能下降 |
| 1 ~ 1.5 | 正常范围 |
| > 1.5 | 碎片较多，需要处理 |

### 5.3 碎片整理

```bash
# 手动整理碎片（Redis 4.0+）
CONFIG SET activedefrag yes

# 自动整理配置
active-defrag-enabled yes
active-defrag-threshold-lower 10
active-defrag-threshold-upper 100
active-defrag-cycle-min 1
active-defrag-cycle-max 25
```

## 六、OOM处理

### 6.1 OOM场景

- 内存使用超过maxmemory
- 淘汰策略为noeviction
- 所有Key都没有设置过期时间

### 6.2 解决方案

```bash
# 1. 增加内存
maxmemory 2gb

# 2. 修改淘汰策略
maxmemory-policy allkeys-lru

# 3. 清理无用Key
DEL key1 key2

# 4. 扩展集群
# 添加新节点分担内存压力
```

## 八、最佳实践

1. **设置maxmemory** — 避免OOM
2. **选择合适策略** — 根据业务场景选择
3. **监控内存** — 关注内存使用和碎片率
4. **避免大Key** — 拆分大Key
5. **设置过期时间** — 及时释放内存
