# 🤝 文档贡献指南

> 帮助你快速上手，写出高质量的技术文档。

---

## 谁应该贡献文档？

**每个人**。文档不是专职文档工程师的事，是整个团队的事。

- 解决了一个棘手的生产问题？→ 写一篇 How-to 文档
- 调研了一个技术方案？→ 写一篇 Explanation 文档
- 搭建了一个新环境？→ 写一篇 Tutorial 文档

> **原则**：你今天踩的坑，帮明天的自己（或同事）跳过去。

---

## 如何贡献

### 第一步：确定文档类型

在写之前，先确定你要写哪种类型的文档：

| 如果你想... | 写这种类型 | 放在 |
|-------------|------------|------|
| 手把手教别人做某件事 | 教程（Tutorial） | `tutorials/` |
| 解决一个具体问题 | 操作指南（How-to） | `how-to/` |
| 记录参数和API | 参考文档（Reference） | `reference/` |
| 解释原理和为什么 | 解释文档（Explanation） | `concepts/` |

### 第二步：选择对应模板

从 [文档模板库](./文档模板库.md) 复制对应模板，填入内容。

**不要从零开始写结构**，模板已经帮你解决了 50% 的问题。

### 第三步：自检

提交前对照以下清单检查：

```
写作质量检查：
☐ 文档头部有 摘要/适用范围/更新时间
☐ 标题能让读者 5 秒内判断这篇文档是否适合自己
☐ 所有代码示例都能正常运行
☐ 没有只有标题没有内容的空章节
☐ 中英文之间有空格（如 "Spring Boot 框架"）
☐ 外部链接已验证可访问
```

### 第四步：放到正确位置

按照以下目录规则放置文档：

```
问自己：这属于哪个技术模块？
  → 04_java_developer/  Java 相关
  → 05_system_architect/ 架构相关
  → work-experience/    项目经验
  → 00_overview/        全局说明
```

## 文件命名规则

```
格式：NN-中文描述.md 或 NN-english-description.md

例子：
✅ 01-系统架构设计.md
✅ 02-如何配置Redis集群.md
✅ 10-getting-started.md

❌ 文档1.md        ← 没有描述
❌ redis.md        ← 不知道讲什么角度
❌ 新建文档.md      ← 临时名字，不要提交
```

**序号规则**：
- `00-09`：概述和入口文档
- `10-49`：主要内容
- `50-79`：进阶内容
- `80-99`：附录、参考

## 更新已有文档

更新文档时，必须：

1. **更新文档头部的 `最后更新` 日期**
2. **如果有重大改动**，在文档末尾添加变更说明：

```markdown
## 变更历史

| 日期 | 变更内容 |
|------|----------|
| 2026-04-22 | 新增 Redis 7.x 集群配置说明 |
| 2026-03-10 | 修正了密码配置示例中的错误 |
```

3. **标注过时内容**（不要直接删除）：

```markdown
> ~~旧的配置方式~~（此方式在 v3.x 中已废弃，请使用新方式）
```

## 什么时候需要写文档？

| 事件 | 需要写什么 |
|------|-----------|
| 解决了一个需要超过 30 分钟排查的 Bug | How-to：如何解决 [问题描述] |
| 完成了新功能开发 | Reference：新功能的使用说明 |
| 技术选型决策 | Explanation：为什么选 A 而不是 B |
| 新人入职/新成员加入 | Tutorial：快速上手指南 |
| 生产事故复盘 | How-to：故障排查手册 |
| 架构改造 | Explanation：新架构设计说明 |

## 常见问题

### Q：我写得不好，应该怎么办？

先写出来，哪怕粗糙。一篇不完美的文档 > 一篇不存在的文档。

你可以在文档顶部加：
```markdown
> ⚠️ **草稿状态**：本文档内容仍在完善中，欢迎反馈。
```

### Q：已有文档有错误，我应该直接改吗？

**可以直接改**。改完更新"最后更新"时间即可。如果改动较大，在变更历史中记一笔。

### Q：同一个主题可以有多篇文档吗？

可以，但它们应该是不同类型的文档：
- 一篇 Tutorial（手把手）
- 一篇 How-to（解决特定问题）
- 一篇 Reference（速查）
- 一篇 Explanation（深入理解）

同类型的同主题文档应该合并。
