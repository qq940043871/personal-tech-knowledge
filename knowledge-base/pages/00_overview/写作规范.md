# ✍️ 技术文档写作规范

> 让每一篇文档都是高质量的作品，而不是凑数的笔记。

---

## 一、核心原则

### 原则 1：读者第一

写文档之前先想清楚三件事：

| 问题 | 说明 |
|------|------|
| **读者是谁？** | 初学者 / 有经验的开发者 / 快速查阅者 |
| **他们想要什么？** | 学会技能 / 解决问题 / 查阅参数 / 理解概念 |
| **他们已经知道什么？** | 确定不用解释什么 |

> ✅ 好文档：读者能在 30 秒内判断这是不是他需要的内容
> ❌ 坏文档：开头是一大段背景介绍，读者不知道自己是否走对了地方

### 原则 2：先写结构，再写内容

动笔前先列大纲。结构清晰了，内容不会乱。

### 原则 3：用例子说话

抽象描述 + 具体例子 = 真正的理解

### 原则 4：宁缺毋滥

一篇高质量的短文档，好过十篇质量平庸的长文档。

## 二、文档头部模板

**每篇文档必须以此格式开头：**

```markdown
# 文档标题（动词 + 名词，直接说明目的）

> 一句话摘要：说明这篇文档是什么、解决什么问题、适合谁阅读。

**适用范围**：Java 8+、Spring Boot 2.x  
**难度级别**：⭐⭐☆☆☆ 初级  
**预计阅读**：10 分钟  
**最后更新**：2026-04-22  

---
```

**字段说明：**
- `适用范围`：明确技术版本，避免读者用错
- `难度级别`：⭐=入门 ⭐⭐=基础 ⭐⭐⭐=进阶 ⭐⭐⭐⭐=高级 ⭐⭐⭐⭐⭐=专家
- `预计阅读`：帮读者决定现在是否有时间读
- `最后更新`：告诉读者文档是否仍然有效

## 三、标题规范

### 标题层级

```markdown
# 文章标题（H1，每篇只有一个）
## 主章节（H2，文档的主要部分）
### 小节（H3，章节内的具体话题）
#### 子小节（H4，可以有，但尽量少用）
```

### 标题命名规则

| 文档类型 | 标题模式 | 示例 |
|----------|----------|------|
| 教程 | 动词开头，描述你要做什么 | "搭建本地开发环境" |
| 操作指南 | "如何..." 或 "配置..." | "如何排查接口超时问题" |
| 参考文档 | 名词，描述内容本身 | "Redis 配置参数说明" |
| 解释文档 | "理解..."、"深入..." | "理解 JVM 垃圾回收机制" |

### ❌ 避免的标题写法

```markdown
# 关于Redis的一些事情    ← 太模糊
# Redis相关              ← 废话标题
# Redis                  ← 不知道这篇讲什么
# 第一章：Redis介绍      ← 书籍格式，不适合文档
```

### ✅ 好的标题写法

```markdown
# Redis 缓存穿透、雪崩、击穿：原因分析与解决方案
# 如何在 K8S 中部署 Redis 集群
# Redis 常用命令速查表
```

## 四、正文写作规范

### 4.1 语气与人称

- **使用第二人称**："你需要先安装 JDK" 而不是 "开发者需要先安装 JDK"
- **使用主动语态**："执行以下命令" 而不是 "以下命令需要被执行"
- **使用现在时**："这个方法返回..." 而不是 "这个方法将会返回..."
- **语气直接，不要绕弯子**

### 4.2 段落规范

- 每段只讲一个重点
- 段落长度控制在 3-5 句
- 大段文字之间用标题或分割线隔开
- 避免出现超过 8 行没有视觉停顿的连续文字

### 4.3 列表使用规范

**有序列表**（步骤有顺序，必须按步骤执行）：
```markdown
1. 安装 JDK 17
2. 配置环境变量
3. 验证安装
```

**无序列表**（项目无顺序，或并列关系）：
```markdown
- 支持 MySQL 5.7+
- 支持 PostgreSQL 12+
- 支持 Oracle 19c+
```

**嵌套列表**：尽量不超过两层，超过请改用表格

### 4.4 强调规范

| 格式 | 用途 | 示例 |
|------|------|------|
| `**粗体**` | 关键术语、重要警告 | **注意：此操作不可逆** |
| `*斜体*` | 专有名词首次出现、书名 | *Spring Cloud Gateway* |
| `` `代码` `` | 代码片段、命令、文件名、参数 | 运行 `mvn clean install` |

**避免滥用强调**：整页都是粗体等于没有强调。

## 五、代码规范

### 5.1 代码块格式

**必须指定语言**（让语法高亮生效）：

````markdown
```java
// Java 代码示例
public class HelloWorld {
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}
```

```bash
# Shell 命令
mvn clean package -DskipTests
docker build -t my-app:latest .
```

```yaml
# YAML 配置
spring:
  application:
    name: my-service
  datasource:
    url: jdbc:mysql://localhost:3306/mydb
```
````

### 5.2 代码示例质量要求

✅ **好的代码示例**：
```java
// 使用 Redis 实现分布式锁
String lockKey = "order:lock:" + orderId;
String lockValue = UUID.randomUUID().toString();
Boolean success = redisTemplate.opsForValue()
    .setIfAbsent(lockKey, lockValue, 30, TimeUnit.SECONDS);

if (Boolean.TRUE.equals(success)) {
    try {
        // 执行业务逻辑
        processOrder(orderId);
    } finally {
        // 释放锁（使用 Lua 脚本保证原子性）
        releaseLock(lockKey, lockValue);
    }
}
```

❌ **差的代码示例**：
```java
// 分布式锁
redis.set(key, value);
doSomething();
redis.del(key);
// 上面代码有严重问题，仅作示例
```

**代码示例必须**：
- [ ] 能在当前主流版本运行
- [ ] 包含必要的错误处理
- [ ] 有注释说明非显而易见的逻辑
- [ ] 示例中的变量名有意义（不用 `a`, `b`, `x`）

### 5.3 命令行规范

```bash
# 注释说明这条命令的作用
mvn clean install

# 期望的输出（可选，帮助读者确认执行成功）
# BUILD SUCCESS
```

当命令需要替换参数时，用 `<>` 标注：
```bash
kubectl apply -f <your-deployment.yaml>
```

## 六、注意事项标注规范

使用以下四种标注：

```markdown
> **💡 提示**：这里有个更简洁的写法...

> **⚠️ 注意**：执行此操作前请先备份数据...

> **🚨 警告**：此操作会删除所有数据，不可恢复！

> **📝 说明**：此行为在 Spring Boot 3.x 中已有变更...
```

渲染效果：
> **💡 提示**：这里有个更简洁的写法...

> **⚠️ 注意**：执行此操作前请先备份数据...

## 七、链接规范

### 内部链接

```markdown
详见 [Redis 部署指南](../05_system_architect/database/redis-deploy.md)
```

**规则**：
- 使用相对路径
- 链接文字要有意义（不用"点击这里"）
- 定期检查链接是否有效

### 外部链接

```markdown
参考 [Spring Boot 官方文档](https://docs.spring.io/spring-boot/docs/current/reference/html/)
```

**规则**：
- 优先链接官方文档
- 外部链接可能失效，重要内容要在本地存一份摘要

## 十、Markdown 格式最佳实践

| 规范 | 说明 |
|------|------|
| 标题后空一行 | 提高可读性 |
| 中英文之间加空格 | "Spring Boot 框架" 而非 "SpringBoot框架" |
| 列表项缩进用 2 个空格 | 保证跨平台一致性 |
| 代码块前后各空一行 | 避免渲染问题 |
| 表格列宽尽量对齐 | 便于维护 |
| 文件末尾保留一个空行 | 避免 Git diff 噪音 |
