# 方法区与元空间

> 模块：运行时数据区
> 更新时间：2026-05-19

## 一、方法区概述

方法区是JVM规范中定义的一个逻辑区域，用于存储已被加载的类信息、常量、静态变量、即时编译器编译后的代码等数据。

```
JDK 7 及之前：
┌──────────────────────────────┐
│         Java堆               │
│  ┌────────────────────────┐  │
│  │    永久代(PermGen)      │  │
│  │  - 类元数据              │  │
│  │  - 常量池               │  │
│  │  - 静态变量              │  │
│  └────────────────────────┘  │
└──────────────────────────────┘

JDK 8 及之后：
┌──────────────────────────────┐
│         Java堆               │
│  (不再包含永久代)             │
└──────────────────────────────┘

┌──────────────────────────────┐
│     本地内存(Metaspace)      │
│  - 类元数据                   │
│  - 运行时常量池               │
└──────────────────────────────┘
```

## 二、PermGen到Metaspace的演变

```java
public class MetaspaceEvolution {

    // JDK 7 永久代的问题
    // 1. 大小固定，容易OutOfMemoryError: PermGen space
    // 2. 与堆内存一起管理，GC效率低
    // 3. 字符串常量池容易溢出

    // JDK 8 元空间的改进
    // 1. 使用本地内存，默认不限大小（受系统内存限制）
    // 2. 类元数据移到本地内存
    // 3. 字符串常量池移到堆中

    // 监控元空间使用
    public static void printMetaspaceInfo() {
        for (MemoryPoolMXBean pool : ManagementFactory.getMemoryPoolMXBeans()) {
            if (pool.getName().contains("Metaspace")) {
                MemoryUsage usage = pool.getUsage();
                System.out.println("Metaspace:");
                System.out.println("  Used:      " + usage.getUsed() / 1024 + " KB");
                System.out.println("  Committed: " + usage.getCommitted() / 1024 + " KB");
                System.out.println("  Max:       " + usage.getMax() / 1024 + " KB");
            }
        }
    }

    // 元空间相关JVM参数
    // -XX:MetaspaceSize=256m       元空间初始大小
    // -XX:MaxMetaspaceSize=512m    元空间最大大小
    // -XX:MinMetaspaceFreeRatio=40 GC后最小空闲比例
    // -XX:MaxMetaspaceFreeRatio=70 GC后最大空闲比例
}
```

## 四、方法区内存管理

```java
public class MetaspaceManager {

    // Chunk管理
    private static final int CHUNK_SIZE = 64 * 1024; // 64KB
    private List<Chunk> freeChunks = new ArrayList<>();
    private List<Chunk> usedChunks = new ArrayList<>();

    // 分配类元数据
    public long allocateClassMetadata(int size) {
        // 对齐到8字节
        int alignedSize = (size + 7) & ~7;

        // 先从空闲Chunk中分配
        Chunk chunk = findFreeChunk(alignedSize);
        if (chunk != null) {
            return chunk.allocate(alignedSize);
        }

        // 空间不足，尝试扩展或触发Full GC
        if (shouldGC()) {
            fullGC(); // 回收无用的类元数据
            chunk = findFreeChunk(alignedSize);
            if (chunk != null) {
                return chunk.allocate(alignedSize);
            }
        }

        // 扩展本地内存
        return expandAndAllocate(alignedSize);
    }

    // 回收类元数据（类卸载时）
    public void deallocateClassMetadata(long address, int size) {
        Chunk chunk = findChunk(address);
        if (chunk != null) {
            chunk.deallocate(address, size);
            if (chunk.isEmpty()) {
                usedChunks.remove(chunk);
                freeChunks.add(chunk);
            }
        }
    }

    // 类卸载条件：ClassLoader被GC回收
    public void unloadClass(Klass klass) {
        if (klass.getClassLoader() != null
                && isClassLoaderUnreachable(klass.getClassLoader())) {
            deallocateClassMetadata(klass.getMetadataAddress(), klass.getMetadataSize());
        }
    }

    static class Chunk {
        long baseAddress;
        int totalSize;
        int usedSize;

        long allocate(int size) {
            if (usedSize + size > totalSize) return -1;
            long addr = baseAddress + usedSize;
            usedSize += size;
            return addr;
        }

        boolean isEmpty() { return usedSize == 0; }
    }
}
```

## 五、运行时常量池在方法区

```java
public class MethodAreaConstantPool {

    // 运行时常量池是方法区的重要组成部分
    private Map<Clazz, RuntimeConstantPool> pools = new HashMap<>();

    public RuntimeConstantPool getOrCreate(Clazz clazz, ConstantPool cp) {
        return pools.computeIfAbsent(clazz, k -> new RuntimeConstantPool(k, cp));
    }

    // 字符串驻留（JDK 7+ 在堆中）
    public String internString(String str) {
        // JDK 7+: 字符串常量池从永久代移到堆中
        // 避免永久代的OOM问题
        return str.intern();
    }
}
```

    public static void generateManyClasses() {

## 七、总结

方法区从永久代演变为元空间，是JVM内存管理的重要改进。理解其演变过程和内部结构，有助于诊断类加载相关的性能问题。

**学习要点**：
1. 理解PermGen到Metaspace的演变原因
2. 掌握类元数据的存储结构
3. 理解元空间的内存管理机制
4. 掌握方法区溢出的排查方法
