## 一、程序计数器概述

程序计数器（Program Counter Register）是一块较小的内存空间，是当前线程所执行的字节码的行号指示器。它是线程私有的，每个线程都有自己独立的程序计数器。

```
线程切换示意：
Thread-1: PC=100 → 执行指令100 → 被挂起
Thread-2: PC=50  → 执行指令50  → 被挂起
Thread-1: PC=100 → 恢复执行
```

## 二、PC寄存器实现

```java
public class ProgramCounter {

    // 线程私有的PC寄存器
    private int pc;

    public ProgramCounter() {
        this.pc = 0;
    }

    // 获取当前PC值
    public int get() {
        return pc;
    }

    // 设置PC值
    public void set(int value) {
        this.pc = value;
    }

    // PC自增（取指令后）
    public void increment(int offset) {
        this.pc += offset;
    }

    // 跳转到指定位置
    public void jump(int target) {
        this.pc = target;
    }
}

public class ThreadContext {

    private ProgramCounter pc;
    private StackFrame currentFrame;
    private JavaStack stack;
    private long threadId;

    public ThreadContext(long threadId) {
        this.threadId = threadId;
        this.pc = new ProgramCounter();
        this.stack = new JavaStack();
    }

    public ProgramCounter getPC() {
        return pc;
    }

    public StackFrame getCurrentFrame() {
        return currentFrame;
    }
}
```

## 三、PC在指令执行中的作用

```java
public class BytecodeInterpreter {

    // 基于PC的指令循环
    public void execute(Method method, ThreadContext context) {
        ProgramCounter pc = context.getPC();
        byte[] code = method.getBytecode();

        while (pc.get() < code.length) {
            // 1. 根据PC读取操作码
            int opcode = code[pc.get()] & 0xFF;
            pc.increment(1);

            // 2. 根据操作码执行指令
            switch (opcode) {
                case 0x10: // bipush
                    int value = code[pc.get()] & 0xFF;
                    pc.increment(1);
                    context.getCurrentFrame().pushInt(value);
                    break;

                case 0x15: // iload
                    int index = code[pc.get()] & 0xFF;
                    pc.increment(1);
                    int local = context.getCurrentFrame().getLocal(index);
                    context.getCurrentFrame().pushInt(local);
                    break;

                case 0x36: // istore
                    int idx = code[pc.get()] & 0xFF;
                    pc.increment(1);
                    int val = context.getCurrentFrame().popInt();
                    context.getCurrentFrame().setLocal(idx, val);
                    break;

                case 0xa7: // goto
                    int branchOffset = ((code[pc.get()] & 0xFF) << 8)
                            | (code[pc.get() + 1] & 0xFF);
                    pc.increment(branchOffset);
                    break;

                case 0x99: // ifeq
                    int offset = ((code[pc.get()] & 0xFF) << 8)
                            | (code[pc.get() + 1] & 0xFF);
                    pc.increment(2);
                    int operand = context.getCurrentFrame().popInt();
                    if (operand == 0) {
                        pc.increment(offset - 2); // 相对跳转
                    }
                    break;

                case 0xb1: // return
                    return;

                default:
                    throw new RuntimeException("Unknown opcode: " + opcode);
            }
        }
    }
}
```

## 四、PC与异常处理

```java
public class ExceptionPC {

    // 异常发生时PC的处理
    public void handleException(ThreadContext context, ExceptionTableEntry[] table,
                                int currentPC, Object exception) {
        // 查找异常处理表
        for (ExceptionTableEntry entry : table) {
            if (currentPC >= entry.startPc && currentPC < entry.endPc) {
                // 检查异常类型是否匹配
                if (entry.catchType == 0 || matchesType(exception, entry.catchType)) {
                    // 跳转到异常处理器
                    context.getPC().set(entry.handlerPc);

                    // 清空操作数栈，压入异常对象
                    StackFrame frame = context.getCurrentFrame();
                    frame.clearOperandStack();
                    frame.pushRef(exception);
                    return;
                }
            }
        }

        // 没有找到处理器，方法异常退出
        throwExceptionToCaller(context, exception);
    }

    // finally块中PC的恢复
    public void handleFinally(ThreadContext context, int returnPC) {
        // 执行finally块
        executeFinallyBlock(context);
        // 恢复原PC
        context.getPC().set(returnPC);
    }
}
```

## 五、PC与线程调度

public class ThreadScheduler {

    // 线程上下文切换时保存/恢复PC
    public void contextSwitch(ThreadContext current, ThreadContext next) {
        // 1. 保存当前线程的PC和其他寄存器状态
        // PC已经在ThreadContext中，无需额外保存

        // 2. 切换到新线程
        vm.setCurrentThread(next);

        // 3. 新线程从其PC位置继续执行
        // PC值由上次挂起时保存
    }

    // 线程挂起
    public void suspend(ThreadContext context) {
        // PC自动保存在线程上下文中
        // 等待调度器重新调度
    }

    // 线程恢复
    public void resume(ThreadContext context) {
        // 从PC位置恢复执行

## 六、PC寄存器的特点

```java
public class PCRegisterFeatures {

    // 特点1：线程私有
    // 每个线程有自己的PC，互不影响

    // 特点2：不会OOM
    // PC是JVM规范中唯一不会抛出OutOfMemoryError的区域

    // 特点3：存储内容
    // - 执行Java方法：存储字节码指令地址
    // - 执行native方法：存储空值（undefined）

    public static void main(String[] args) {
        // 每个线程启动时PC初始化为0
        Thread t1 = new Thread(() -> {
            // t1的PC从main方法的第一条指令开始
            System.out.println("Thread-1 running");
        });

        Thread t2 = new Thread(() -> {
            // t2的PC从其run方法的第一条指令开始
            System.out.println("Thread-2 running");
        });

        t1.start();
        t2.start();
        // 两个线程的PC完全独立
    }
}
```

## 七、总结

程序计数器是JVM中最小但最重要的内存区域，它确保了线程切换后能恢复到正确的执行位置。

**学习要点**：
1. 理解PC寄存器的线程私有特性
2. 掌握PC在指令执行中的作用
3. 理解PC在异常处理中的行为
4. 掌握线程切换时PC的保存与恢复
