## 一、推理加速技术栈

```
推理加速方案：
  1. PagedAttention（vLLM）
     - KV Cache分页管理
     - 解决显存碎片化
     - 吞吐量提升2-4倍

  2. Continuous Batching（TGI）
     - 动态batch，不等最慢请求
     - 新请求随时加入batch
     - 延迟降低50%+

  3. Tensor并行
     - 模型切分到多GPU
     - 单请求延迟不变
     - 吞吐量线性扩展

  4. Speculative Decoding
     - 小模型草稿 + 大模型验证
     - 加速比1.5-3倍
     - 输出质量不变
```

## 二、vLLM部署

```python
from vllm import LLM, SamplingParams


class VLLMEngine:
    """vLLM推理引擎"""

    def __init__(self, model_path: str, tensor_parallel: int = 1,
                 gpu_memory_utilization: float = 0.9):
        self.llm = LLM(
            model=model_path,
            tensor_parallel_size=tensor_parallel,
            gpu_memory_utilization=gpu_memory_utilization,
            max_model_len=8192,
            enable_prefix_caching=True,    # 前缀缓存
        )

    def generate(self, prompts: List[str],
                 temperature: float = 0.7,
                 max_tokens: int = 512) -> List[str]:
        """批量生成"""
        sampling_params = SamplingParams(
            temperature=temperature,
            max_tokens=max_tokens,
            top_p=0.9,
        )
        outputs = self.llm.generate(prompts, sampling_params)
        return [output.outputs[0].text for output in outputs]

    async def generate_stream(self, prompt: str,
                               max_tokens: int = 512):
        """流式生成"""
        sampling_params = SamplingParams(
            temperature=0.7,
            max_tokens=max_tokens,
        )
        async for output in self.llm.generate_async(prompt, sampling_params):
            yield output.outputs[0].text
```

## 三、Continuous Batching实现

```python
import asyncio
from dataclasses import dataclass, field
from typing import List, Dict, AsyncIterator


@dataclass
class BatchRequest:
    """批处理请求"""
    request_id: str
    prompt: str
    max_tokens: int
    temperature: float = 0.7
    generated_tokens: List[int] = field(default_factory=list)
    is_complete: bool = False


class ContinuousBatchScheduler:
    """Continuous Batching调度器"""

    def __init__(self, engine, max_batch_size: int = 32,
                 max_queue_size: int = 100):
        self.engine = engine
        self.max_batch_size = max_batch_size
        self.queue: asyncio.Queue = asyncio.Queue(maxsize=max_queue_size)
        self.active_requests: Dict[str, BatchRequest] = {}

    async def submit(self, request: BatchRequest) -> AsyncIterator[str]:
        """提交请求，返回流式结果"""
        result_queue = asyncio.Queue()
        self.active_requests[request.request_id] = (request, result_queue)
        await self.queue.put(request)

        while True:
            token = await result_queue.get()
            if token is None:  # 完成信号
                break
            yield token

    async def run(self):
        """调度主循环"""
        while True:
            # 收集当前batch
            batch: List[BatchRequest] = []

            # 从活跃请求中收集未完成的
            for req_id, (req, _) in list(self.active_requests.items()):
                if not req.is_complete:
                    batch.append(req)

            # 从队列中取新请求
            while len(batch) < self.max_batch_size and not self.queue.empty():
                new_req = await self.queue.get()
                batch.append(new_req)

            if not batch:
                await asyncio.sleep(0.01)
                continue

            # 执行一步推理
            next_tokens = self.engine.step_batch(batch)

            # 分发结果
            for req, token in zip(batch, next_tokens):
                req.generated_tokens.append(token)
                _, result_queue = self.active_requests[req.request_id]
                await result_queue.put(token)

                # 检查是否完成
                if token == self.engine.eos_token_id or \
                   len(req.generated_tokens) >= req.max_tokens:
                    req.is_complete = True
                    await result_queue.put(None)  # 完成信号
                    del self.active_requests[req.request_id]
```

## 四、PagedAttention原理

```
传统KV Cache：
  - 每个请求预分配最大长度的连续显存
  - 浪费严重（实际生成长度远小于最大长度）
  - 显存碎片化

PagedAttention：
  - KV Cache分成固定大小的Page（如16 tokens/page）
  - 按需分配，用完再申请
  - 支持Page共享（相同前缀的请求共享KV）
  - 显存利用率从20-40%提升到90%+

显存管理：
  ┌──────────────────────────────────┐
  │  Physical Pages Pool              │
  │  [Page0][Page1][Page2][Page3]... │
  └──────────────────────────────────┘
        ↑       ↑       ↑
     Req A   Req B   Req C
  （逻辑连续，物理不连续）
```
