> 版本：v1.0  
> 建立日期：2026-04-22  
> 维护人：技术团队  
> 适用范围：所有工程项目 & 知识库

---

## 一、为什么文档是工程的一部分

**文档不是"写完代码再说"的事。** 没有文档的代码是未完成的代码。

核心判断依据：
- 新成员入职后多久能独立上手？→ 靠文档
- Bug 修复时能快速定位上下文吗？→ 靠文档
- 半年后你还记得当时为什么这样设计吗？→ 靠文档
- 对接方能自助完成 API 集成吗？→ 靠文档

> **文档债务和技术债务一样危险，且更难察觉。**

## 二、文档分类体系（Divio 四象限）

本体系采用业界认可的 **Divio 文档系统**，将所有文档分为四类，每类有明确边界：

```
┌──────────────────────────────────────────────────────────────┐
│                      文档四象限                               │
├─────────────────────────┬────────────────────────────────────┤
│   📚 教程 Tutorial       │   🧭 操作指南 How-to Guide          │
│   学习导向 · 动手实践     │   任务导向 · 解决具体问题           │
│   "带我从零做一遍"       │   "我要做 X，怎么做"               │
│   ─────────────────────── │   ────────────────────────────── │
│   面向：初学者            │   面向：有经验的用户               │
│   目标：学习过程          │   目标：完成特定任务               │
├─────────────────────────┼────────────────────────────────────┤
│   📖 参考文档 Reference   │   💡 概念解释 Explanation          │
│   信息导向 · 查阅手册     │   理解导向 · 解释背景              │
│   "X 有哪些参数/选项"    │   "为什么这样设计"                 │
│   ─────────────────────── │   ────────────────────────────── │
│   面向：使用中的开发者    │   面向：想深入理解的读者           │
│   目标：快速查到准确信息  │   目标：建立心智模型               │
└─────────────────────────┴────────────────────────────────────┘
```

**关键原则：一篇文档只做一件事。** 不要把教程和参考文档混在一起写。

## 三、文档目录规范

### 3.1 项目级文档结构

每个工程项目应包含以下文档，按优先级排序：

```
项目根目录/
├── README.md                    # [必须] 项目门面，30秒让人明白项目是什么
├── docs/
│   ├── getting-started.md       # [必须] 快速上手（教程类）
│   ├── architecture.md          # [推荐] 架构设计说明（概念类）
│   ├── api/
│   │   ├── overview.md          # API 概述、认证、错误码
│   │   ├── user.md              # 用户相关接口
│   │   ├── agent.md             # 智能体相关接口
│   │   └── ...                  # 按模块拆分
│   ├── guides/
│   │   ├── deployment.md        # 部署指南（操作指南类）
│   │   ├── configuration.md     # 配置说明
│   │   └── troubleshooting.md   # 故障排查
│   ├── design/
│   │   ├── database.md          # 数据库设计文档
│   │   └── workflow.md          # 业务流程说明
│   └── changelog/
│       └── CHANGELOG.md         # 版本变更记录
└── CONTRIBUTING.md              # [推荐] 贡献指南（包含文档贡献规范）
```

### 3.2 知识库级文档结构

针对学习型知识库（如当前工作区的各类指南）：

```
知识库名称/
├── 00-总览与索引.md             # [必须] 目录 + 学习路径
├── 01-XXX基础篇/
│   ├── 01-概念入门.md
│   └── 02-基础语法.md
├── 02-XXX进阶篇/
│   ├── 01-高级特性.md
│   └── 02-实战案例.md
└── 99-参考速查.md               # 快速查找的速查表
```

## 四、文档生命周期管理

### 4.1 文档随代码发布

| 场景 | 文档要求 |
|------|---------|
| 新功能上线 | 同 PR 包含对应功能文档 |
| API 变更 | 更新 API 参考文档 + 如有破坏性变更需写迁移指南 |
| 配置项变更 | 更新配置说明文档 |
| Bug 修复 | 如影响使用方式，更新相关操作指南 |
| 版本发布 | 追加 CHANGELOG 条目 |

**规则：没有文档的代码 PR 不予合并。**

### 4.2 文档健康状态

每季度对文档进行一次健康检查：

```
文档健康分级：
🟢 健康   — 内容准确，版本匹配，3个月内有人维护
🟡 待更新 — 内容基本正确但需要补充，或版本落后1个小版本
🔴 过时   — 与当前代码不符，或超过6个月无人维护
⚫ 废弃   — 功能已下线，文档存档但不再维护
```

### 4.3 文档版本管理

- 文档版本随软件语义版本控制对齐（MAJOR.MINOR.PATCH）
- 破坏性变更（MAJOR）必须保留旧版文档并标注 `[Deprecated]`
- 永远不要删除已发布的文档，使用归档代替删除

## 五、文档质量门禁

### 5.1 README 五秒测试

一个合格的 README，任何陌生人在 5 秒内必须能回答：

- [ ] **这是什么？** —— 一句话描述
- [ ] **我为什么要用它？** —— 解决什么问题
- [ ] **怎么开始？** —— 最短路径到可运行状态

### 5.2 代码示例标准

- [ ] 所有代码示例**必须可运行**（发布前在干净环境中测试过）
- [ ] 注明运行环境：语言版本、依赖版本
- [ ] 包含预期输出（`// 输出：xxx`）
- [ ] 复杂示例提供可运行的完整项目链接

### 5.3 API 文档完整性

每个公开 API 接口必须包含：

- [ ] 接口用途（一句话）
- [ ] 请求方式 + 路径
- [ ] 认证方式
- [ ] 请求参数表（字段名、类型、必选/可选、说明）
- [ ] 成功响应示例
- [ ] 错误响应示例（至少 2 种常见错误）
- [ ] 使用注意事项（限流、特殊规则等）

## 六、文档工具链推荐

| 用途 | 推荐工具 | 说明 |
|------|---------|------|
| 文档站点 | VitePress / Docusaurus | Markdown 驱动，支持搜索 |

| 截图标注 | Snipaste | 操作类文档的截图工具 |
