## 一、死锁原理

```
死锁条件（四个必要条件）：
  1. 互斥：资源被独占
  2. 持有并等待：持有A等待B
  3. 不可剥夺：不能抢占他人资源
  4. 循环等待：形成等待环

数据库死锁示例：
  事务T1: UPDATE accounts SET balance=100 WHERE id=1 (锁id=1)
  事务T2: UPDATE accounts SET balance=200 WHERE id=2 (锁id=2)
  事务T1: UPDATE accounts SET balance=150 WHERE id=2 (等待id=2)
  事务T2: UPDATE accounts SET balance=250 WHERE id=1 (等待id=1)
  → T1等T2，T2等T1，死锁！
```

## 二、等待图检测

```java
public class DeadlockDetector {
    /** 等待图：transactionId → 等待的 transactionId */
    private Map<Long, Long> waitForGraph = new ConcurrentHashMap<>();

    /** 事务请求锁时，记录等待关系 */
    public void addWaitEdge(long waiter, long holder) {
        waitForGraph.put(waiter, holder);
    }

    /** 事务获取锁后，移除等待关系 */
    public void removeWaitEdge(long transactionId) {
        waitForGraph.remove(transactionId);
    }

    /** 检测是否有环（死锁） */
    public List<Long> detectCycle() {
        Set<Long> visited = new HashSet<>();
        Set<Long> inStack = new HashSet<>();

        for (Long node : waitForGraph.keySet()) {
            List<Long> cycle = dfs(node, visited, inStack, new ArrayList<>());
            if (cycle != null) {
                return cycle;
            }
        }
        return null; // 无死锁
    }

    private List<Long> dfs(long node, Set<Long> visited,
                           Set<Long> inStack, List<Long> path) {
        if (inStack.contains(node)) {
            // 找到环，提取环中的节点
            int idx = path.indexOf(node);
            return path.subList(idx, path.size());
        }
        if (visited.contains(node)) {
            return null;
        }

        visited.add(node);
        inStack.add(node);
        path.add(node);

        Long next = waitForGraph.get(node);
        if (next != null) {
            List<Long> cycle = dfs(next, visited, inStack, path);
            if (cycle != null) return cycle;
        }

        path.remove(path.size() - 1);
        inStack.remove(node);
        return null;
    }

    /** 选择牺牲者（回滚代价最小的事务） */
    public long selectVictim(List<Long> cycle) {
        return cycle.stream()
            .min(Comparator.comparingLong(this::rollbackCost))
            .orElse(cycle.get(0));
    }

    private long rollbackCost(long transactionId) {
        // 考虑：已执行时间、已修改行数、持有的锁数
        return getModifiedRows(transactionId) + getHeldLocks(transactionId);
    }
}
```

## 三、死锁预防策略

```
预防方案：
  1. Wait-Die（老等新）
     - 老事务等待新事务
     - 新事务请求老事务持有的锁 → 直接回滚

  2. Wound-Wait（新等老）
     - 新事务等待老事务
     - 老事务请求新事务持有的锁 → 回滚新事务

  3. 超时检测
     - 等待锁超过阈值 → 回滚
     - 简单但可能误杀

  4. 按序加锁
     - 所有事务按固定顺序获取锁
     - 从根本上避免循环等待
```
