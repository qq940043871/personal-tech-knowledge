## 一、Redis为什么用单线程

### 1.1 单线程的优势
- **无锁竞争** — 避免线程切换和锁的开销
- **简单高效** — 代码逻辑简单，易于维护
- **内存操作** — 纯内存操作，CPU不是瓶颈

### 1.2 单线程的限制
- **无法利用多核** — 单个实例只能使用一个CPU核心
- **大Key阻塞** — 操作大Key会阻塞其他请求

### 1.3 Redis 6.0多线程
Redis 6.0引入多线程IO，但命令执行仍然是单线程：

```
网络IO（多线程） → 命令执行（单线程） → 网络IO（多线程）
```

## 二、IO多路复用

### 2.1 什么是IO多路复用

IO多路复用允许单个线程同时监听多个文件描述符（FD），当某个FD就绪时通知应用程序。

### 2.2 实现方式

| 方式 | 平台 | 特点 |
|------|------|------|
| select | 跨平台 | 最大监听1024个FD |
| poll | 跨平台 | 无FD数量限制 |
| epoll | Linux | 高性能，事件驱动 |
| kqueue | BSD/Mac | 类似epoll |

### 2.3 epoll工作原理

```
1. 创建epoll实例
2. 注册FD到epoll
3. 等待事件（epoll_wait）
4. 处理就绪事件
```

```c
// 创建epoll实例
int epfd = epoll_create(1);

// 注册FD
struct epoll_event ev;
ev.events = EPOLLIN;
ev.data.fd = sockfd;
epoll_ctl(epfd, EPOLL_CTL_ADD, sockfd, &ev);

// 等待事件
struct epoll_event events[1024];
int nfds = epoll_wait(epfd, events, 1024, -1);

// 处理事件
for (int i = 0; i < nfds; i++) {
    if (events[i].events & EPOLLIN) {
        // 处理读事件
    }
}
```

## 三、Redis事件模型

### 3.1 事件类型

- **文件事件** — 套接字读写事件
- **时间事件** — 定时任务（如过期Key清理）

### 3.2 事件循环

```c
void aeMain(aeEventLoop *eventLoop) {
    eventLoop->stop = 0;
    while (!eventLoop->stop) {
        // 处理时间事件
        processTimeEvents(eventLoop);
        
        // 处理文件事件
        aeApiPoll(eventLoop, tvp);
        processFileEvents(eventLoop);
    }
}
```

## 四、请求处理流程

```
客户端发送命令
    ↓
IO多路复用检测到可读事件
    ↓
读取命令到输入缓冲区
    ↓
解析命令
    ↓
执行命令
    ↓
写入输出缓冲区
    ↓
IO多路复用检测到可写事件
    ↓
发送响应给客户端
```

## 五、性能优化

### 5.1 避免大Key

```bash
# 查看Key大小
MEMORY USAGE key

# 拆分大Key
# 大Hash → 多个小Hash
# 大List → 多个小List
```

### 5.2 使用Pipeline

```python
# 批量操作减少网络往返
pipe = redis.pipeline()
for i in range(10000):
    pipe.set(f"key:{i}", f"value:{i}")
pipe.execute()
```

### 5.3 合理设置超时

```conf
# 客户端超时
timeout 300

# TCP keepalive
tcp-keepalive 300
```

## 七、常见问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
